# P1–P10 帧识别逻辑

本文说明两个视频工作流（`workflow.py` 与 `python -m golfpose_workflow`）如何从一段挥杆视频中选出 P1–P10 十个关键帧。两个工作流的 2D 检测方式不同，但从 2D 关键点开始的帧识别逻辑完全共用，入口都是 `golf_workflows/golf_pose_3d.py` 的 `process`。

所有阈值均来自当前代码；文中“躯干长度”指准备阶段根节点到胸部（thorax）的 2D 像素距离中位数，用来把像素距离换算成与人体尺寸无关的单位。

## 1. 位置定义

定义参照 HackMotion 的 P 分类（hackmotion.com/golf-swing-positions）：

| 位置 | 名称 | 判定依据 |
| --- | --- | --- |
| P1 | 准备站位（address） | 杆头静止在球后的最后时刻 |
| P2 | 起杆（takeaway） | 杆身与地面平行 |
| P3 | 上杆半程（halfway back） | 前导臂与地面平行 |
| P4 | 上杆顶点（top） | 球杆停止向后转动 |
| P5 | 下杆初段（early downswing） | 前导臂下落经过平行 |
| P6 | 击球前（pre-impact） | 杆身与地面平行 |
| P7 | 击球（impact） | 杆头到达球 |
| P8 | 释放（release） | 击球后双臂最伸直 |
| P9 | 收杆（finish） | 前导臂上升经过平行 |
| P10 | 结束（end） | 双手举高、停在前导侧耳旁 |

右手球手的前导侧（lead side）是左侧；左手球手相反。

## 2. 总体流程

1. **2D 检测**：每帧得到人体关节、球杆标记点（握把 `shaft`、杆颈 `hosel`）及置信度。
   - `workflow.py`：YOLO26n 人体（在双类 YOLOX 人物框内）＋双类 YOLOX 球杆框＋仅球杆 ViTPose-H。
   - golfpose：单类 YOLOX 球手框＋22 点联合 ViTPose-H；低置信度人体关节由 YOLO26n 补充。
   - 两者在球杆置信度低于 0.3 时，都会沿“预测杆身”重新裁剪一次再推理（只在置信度提高时采用）。
2. **视角与左右手习惯**：自动判断（第 3 节）。
3. **球杆跟踪**：用刚性杆模型清洗球杆检测（第 4 节）。
4. **阶段识别（2D）**：确定 P1、P4、P7 和送杆结束帧（第 5 节）。
5. **球的位置修正 P7**（第 6 节）。
6. **3D 提升**：MixSTE 只在 P1 到送杆结束之间的窗口内把 2D 提升为 3D，并拟合刚性球杆。
7. **其余位置（3D）**：P2、P3、P5、P6、P8、P9、P10 以 P1/P4/P7 为边界，分三段联合选取（第 7 节）。
8. **输出**：帧号、每个位置的置信度、亚帧时间，以及旧规则的结果对照（第 10 节）。

第 4 步与第 6 步之间还有一道骨架质量检查（第 8 节）：挥杆窗口内骨架丢失太久时直接中止。

坐标约定：图像 y 轴向下，因此“高度”= −y；3D 姿态以根节点为原点，沿用相机坐标轴。

## 3. 视角与左右手习惯（`position_selection.py`）

`--view` 与 `--handedness` 默认 `auto`，取前 10 个关键关节都可靠的帧（即准备阶段）判断；无法判断时回退到 `down_the_line` / `right`，并在 `view_detection` / `handedness_detection` 中记录原因。

**视角**：
- 两肩宽度 / 躯干长度 ≥ 0.35，且双脚连线与水平夹角 < 25° → 正面视角（face-on）。
- 两肩宽度 / 躯干长度 < 0.25，或双脚连线夹角 ≥ 30° → 后方视角（down-the-line）。后方视角两肩几乎重叠，双脚处在不同深度，连线很陡。
- 其余情况视为不明确，使用默认值。

**左右手习惯**：
- 后方视角：准备时双手位于髋部的图像右侧（≥ 0.2 躯干长度）→ 右手；位于左侧（≤ −0.2）→ 左手。
- 正面视角：上杆顶点（双手最高帧）时，双手相对准备位置向图像左侧移动 ≥ 0.3 躯干长度 → 右手；向右侧移动 ≥ 0.3 → 左手。

**地面校平（仅正面视角）**：正面视角下双脚在同一深度，连线在水平画面中应是水平的。若其倾斜 ≤ 10°，就视为相机滚转，在选取 P2–P10 之前把 3D 姿态绕相机轴反向旋转该角度。后方视角不做校平。结果记录在 `checkpoint_selection.ground_leveling`。

## 4. 球杆跟踪（`club_tracking.py`、`club_measurements.py`）

帧识别大量依赖杆头位置，所以先对球杆检测做清洗：

- **模型**：以双手为锚点的刚性杆，状态为杆身角度及角速度，用恒角速度卡尔曼滤波前向一遍，再用 RTS 平滑。
- **握把/杆颈方向**：握把一定在手的一端。两端到手的距离差 ≥ 杆长 25% 时，方向由几何确定，连续性不得反转；只有两端距离相近（球杆透视缩短）时才允许按连续性判定互换。
- **接受与剔除**：置信度 ≥ 0.5 的检测始终接受，与预测不符时以它重新初始化。低置信度检测若偏离预测超过 3σ（且超过 20°），判为误检并剔除，下游不再视为有效观测。
- **补充角度测量**：检测不可靠的帧上，再用两种只含角度的观测：手部周围的运动模糊条纹（直线拟合）和球杆分割掩膜的主轴。在 005 上与可靠检测相比，条纹中位误差约 1°，掩膜约 2.4°。
- **输出**：每帧的握把/杆颈位置、角度不确定度（`club_track_sigma_deg`），以及接受、剔除、互换帧列表（`club_tracking`）。

“可靠球杆帧”指跟踪后仍有效、且握把与杆颈两点置信度中较低者 ≥ 0.3（`RELIABLE_CLUB_CONFIDENCE`）的帧。

## 5. P1、P4、P7 与送杆结束（`swing_phases.detect_refined_phases`）

这一步使用 2D 数据，因为 3D 提升的时间窗口需要先由它决定。

**基础信号**：
- 手部位置 = 两腕中点相对根节点的位移 ÷ 躯干长度，再做时间平滑；手部高度取其 −y。
- 球杆信号 = 杆颈相对根节点的位移 ÷ 躯干长度；只采用握把距离双手 ≤ 0.8 躯干长度的检测。
- 手部高度变化幅度不足 0.15 时，判为没有完整挥杆，回退到旧的杆头速度规则。

**手部上升与回落**：在手部高度上找突出度 ≥ 25% 幅度的峰（上杆）和谷（回落），每个峰与其后的第一个谷配成一组，选落差最大的一组。峰为 `wrist_top`，谷为 `wrist_impact`。

**P4 上杆顶点**：
- 在 `wrist_top` 前后 0.15 秒内，用可靠球杆帧（投影长度 ≥ 0.4 躯干长度）的 2D 杆身角度，找球杆停止向后转、开始回转的帧（两侧都要回转至少 3°）。
- 找到则 P4 = 该帧（`top_source: club_reversal`）；否则 P4 = `wrist_top`（`wrist_peak`）。手往往先到最高点，球杆还在继续上杆，所以优先看球杆。

**P7 击球（未用球之前）**：
- 默认 P7 = `wrist_impact`。
- 在 `wrist_impact` ± max(2, round(0.12·fps)) 帧内、P4 之后，取杆头最接近准备时杆头位置的检测帧。准备位置取前 max(2, min(8, P4÷3)) 帧杆头位置的中位数。
- 若该距离 ≤ max(0.15, 0.35 × 上杆最大偏移)，P7 改为这一帧。

**P1 准备站位**：
- 手部启动：手部偏离初始位置 ≥ max(0.06, 0.1 × 上杆前最大偏移)，且连续 max(2, round(0.06·fps)) 帧，再往前推 0.1 秒。
- 杆头静止（优先）：可靠帧中杆头距准备位置 < max(0.1, 0.1 × 上杆偏移) 视为静止，取 P4 之前、最后一次开始移动之前的最后静止帧；0.3 秒内至少要有两帧静止。单帧跳动 > 0.6 躯干长度的检测视为误检并忽略（起杆很慢）。
- 找到杆头静止时，P1 = min(静止结束 + 1 − round(0.1·fps), P4 − 2)（`address_source: club_rest`）；否则用手部启动（`hand_motion_onset`）。杆头比手先动、动得更远，所以优先用杆头，也能跳过早先的预备摆动（waggle）。

**送杆结束（3D 窗口终点）**：
- 手部速度 < max(0.08, 0.18 × 速度 95 分位)，手高于击球与顶点高度的中点，且在 P7 之后至少 max(2, round(0.15·fps)) 帧，连续保持 max(3, round(0.25·fps)) 帧，视为收杆静止。
- 窗口一直延伸到双手重新放下（连续 max(2, round(0.1·fps)) 帧低于中点）为止，以免截掉 P10；没有静止或手始终未放下时，延伸到视频末尾。

## 6. 用球修正 P7（`golf_pose_3d.track_ball`、`impact_from_ball`）

- YOLOE 分割模型（`yoloe-26n-seg.pt`，类别 `golf ball`）在 P1 前 8 帧到后 5 帧内寻找球，得到球的位置 `ball.p1_xy`。
- 在 `wrist_impact` ± max(2, round(0.2·fps)) 帧内，取杆颈检测离球最近的帧；若这一最近距离超过 0.6 躯干长度，则不采用。
- 采用时，以该帧为提示重新运行第 5 节；提示帧与 `wrist_impact` 的差距在上述窗口内才接受（`ball_impact_hint_accepted`）。
- 结果中的 `ball.p7_clubhead_distance_px` 是 P7 时杆颈到球的像素距离，可用来检查 P7 是否可信。正常应在几十像素以内，几百像素说明杆头位置有误。

## 7. 其余位置：联合选取（`position_selection.select_positions`）

P1、P4、P7 把挥杆切成三段：上杆段（P1, P4）选 P2、P3；下杆段（P4, P7）选 P5、P6；送杆段（P7 之后）选 P8、P9、P10。

旧规则（`find_checkpoint_frames`）是一个接一个地贪心选取，一个位置选错，后面的都会跟着偏。现在给每个候选帧、每个位置都算一个代价，再在每段内用动态规划一起选出总代价最小、且严格按顺序（至少相隔 1 帧）的组合。

这一步用的是 3D 姿态（正面视角时先校平），信号都经过 5 帧 Savitzky–Golay 平滑；该平滑是对称的，不会让过零点偏移。

**基础量**：
- **双手**：前导侧手腕；当它的 2D 置信度 < 0.3（被遮挡）且后侧手腕更可信时，按两者置信度加权混合。两手握在同一根握把上，相距只有几厘米。用到后侧手腕的帧记录在 `trail_wrist_frames`。
- **前导臂仰角**：前导肩到双手连线与水平面的夹角，高于肩为正。
- **杆身倾角**：3D 握把到杆颈连线与水平面的夹角。
- **肘伸展**：左右肘角的平均值，180° 为完全伸直。

**各位置代价**（每 5° 计 1 个代价单位）：

| 位置 | 候选帧 | 代价 |
| --- | --- | --- |
| P2 | P1 与 P4 之间 | 取两者较小者：① 可靠球杆帧上的杆身倾角；② 前导臂仰角与目标值之差，加 2 作为“未看到球杆”的惩罚。目标值 = P1 时仰角 + 0.3 × (0 − P1 时仰角)，即前导臂从下垂到水平转过 30% 的位置；在 005、008 的可靠帧上，杆身平行时手臂约转过 25–30%。 |
| P3 | P1+2 到 P4−1 | \|前导臂仰角\|；第一次向上穿过水平之后，每晚一帧加 1，避免选到后面的再次穿越。 |
| P5 | P4+1 到 P7−2 | \|前导臂仰角\|，取向下穿过水平；规则同 P3。 |
| P6 | P4 与 P7 之间 | 同 P2，目标值以 P7 时仰角为下垂端。 |
| P8 | P7 之后、双手已抬升的帧 | 双手相对肩的高度须至少达到“击球时高度 + 25% × (P9 时高度 − 击球时高度)”，因为击球时手臂同样伸直。代价 = max(0, 最大伸展 − 本帧伸展 − 5°)，再加杆身倾角 ÷ 90° 作为小幅的平局决胜（只计可靠球杆帧，否则加 1）。 |
| P9 | P7+2 到最后一个有效帧 | \|前导臂仰角\|，取向上穿过水平；第一次穿越后，每晚一帧加 1。之后的收杆和放杆还会再次经过水平。 |
| P10 | 收杆区间内、双手高于肩的帧 | 双手到头部的 3D 距离 ÷ 躯干长度 × 5。收杆区间 = P7 之后双手最高点附近、高度不低于“最高点 − 5% × (最高点 − 击球时高度)”的连续帧。 |

**置信度**：对每个位置，比较“最优组合的总代价”与“把该位置强制挪开 2 帧以上后的最优总代价”，差值记为 margin，置信度 = 1 − exp(−margin / 2)。接近 1 表示明确，接近 0 表示附近有几乎同样好的候选帧，值得人工复核。结果在 `checkpoint_selection.position_confidence`。

**亚帧时间**：
- P3、P5、P9：在平滑后的仰角上线性插值出过零时刻。
- P2、P6：若由杆身决定，取倾角极小值处的抛物线顶点；若由手臂决定，取仰角穿过目标值的时刻。
- P8：伸展角极大值处的抛物线顶点。
- P10：手头距离极小值处的抛物线顶点。

最终帧号仍取最近的整数帧；亚帧时间（帧与毫秒）保存在 `subframe_frames` / `subframe_ms`，供后续评分做时间对齐。

**P2/P6 的依据**记录在 `position_sources`：`observed_shaft`（看到了杆身）或 `lead_arm_progress`（用手臂代替）。

## 8. 骨架质量检查（中止条件）

第 5 节确定挥杆窗口后、3D 提升前，`golf_pose_3d.check_skeleton` 会检查 P1 到送杆结束之间的 2D 骨架：

- **丢失帧**：根节点、双髋、双肩、双肘、双腕这 9 个核心关节中有效的少于 6 个，或两腕都缺。
- **中止条件**：连续丢失超过 max(3 帧, 0.3 秒)，或丢失帧超过窗口的 15%。满足任一条件时，打印 `ERROR:` 并抛出 `SkeletonQualityError`，错误信息列出丢失帧段及其时长，命令以错误退出。
- **诊断文件**：无论是否通过，都写入 `skeleton_diagnostics.json`，字段在结果 JSON 的 `skeleton_check` 中也有一份。
- `--allow-skeleton-gaps` 把中止改为警告，适合确认遮挡无害时使用。

正常情况下，2D 检测阶段已经会自动纠正漂移的人体裁剪框（在上一帧骨架范围和球手 ROI 中重试），所以这个检查拦下的是纠正后仍然无法恢复的情况。

## 9. 回退与人工覆盖

- 关闭球杆 refinement（`--no-club-refinement`）时，使用旧的杆头/手腕速度规则确定阶段，再用旧的逐个贪心规则选位置。两个工作流默认都开启 refinement。
- P1、P4、P7 中任一缺失时无法联合选取，回退到旧规则。
- `--positions-json` 提供人工复核的 P1–P10 时，直接使用这些帧，不做自动识别。

## 10. 输出字段（`<stem>_3d.json`）

| 字段 | 内容 |
| --- | --- |
| `positions` | P1–P10 帧号（从 0 开始） |
| `phases`、`phase_detection` | P1/P4/P7/送杆结束，以及 `top_source`、`address_source`、`wrist_impact`、`ball_impact_hint_accepted` 等依据 |
| `ball` | 球位置与 `p7_clubhead_distance_px` |
| `checkpoint_selection.selector` | `joint_dp`（联合选取）或旧规则 |
| `checkpoint_selection.position_confidence` | 每个位置的置信度 |
| `checkpoint_selection.subframe_frames` / `subframe_ms` | 亚帧时间 |
| `checkpoint_selection.rule_based_positions` | 旧贪心规则的结果，用于对照 |
| `checkpoint_selection.position_sources` | P2/P6 的依据 |
| `checkpoint_selection.ground_leveling`、`trail_wrist_frames` | 校平角度、使用后侧手腕的帧 |
| `view_detection`、`handedness_detection` | 自动判断的依据 |
| `club_tracking` | 球杆跟踪的接受、剔除、互换统计 |

## 11. 评估与已知局限

- 基准：`benchmarks/p_position_labels.json` 保存人工标注的帧范围（目前是部分种子集：w09、005、008、010）。
  - `python -m golf_workflows.benchmark evaluate <运行目录>` 计算每个位置偏离标注的帧数和毫秒数。
  - `python -m golf_workflows.benchmark replay --out <目录>` 用已保存的 2D 重新跑识别，不重跑 2D 模型。
- 这些都是针对单次挥杆的启发式规则，不是训练出来的阶段分类模型；一段视频里有多次挥杆时，只取手部落差最大的一次。
- 30 fps 左右时，击球前后相邻帧之间杆身可转过 60° 以上，P5–P8 的帧级误差至少 ±1 帧；亚帧时间可以部分弥补这一点。
- 前导臂被身体遮挡时（如 w09 第 33 帧），P9 会在相邻两帧之间摇摆。
- 上杆顶点附近球杆常常模糊或出画，P4 经常只能退回到手腕峰值。
