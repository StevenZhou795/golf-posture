# SwingTrace 球杆数据与 P1–P10 依据

本次只完成接入、自检及合成图推理。尚未使用 SwingTrace 跑真实视频，不能据此声称动作识别准确或给出完整视频加速倍数。

## 模型数据

本地权重：`models/swingtrace-yolo11m.pt`。已核验模型为 Ultralytics 检测模型，类别映射与[模型说明](https://huggingface.co/nishsm/golf-club-detection-swingtrace)一致：

| 类别 ID | 权重中的名称 | 含义 | 使用方式 |
| --- | --- | --- | --- |
| 0 | `0` | 杆身 | 保存原始框，框中心作为杆身位置代理 |
| 1 | `1` | 杆头 | 保存原始框，框中心作为杆头位置代理 |
| 2 | `3` | 双手／握把 | 关联 RTMW 检出的球手手腕，检查杆身和杆头是否属于同一球杆 |

这是三个类别的检测框，不是三个精确关键点。每帧进行一次 640 输入的 FP32 检测，不加载球杆 ViTPose，不用球杆分割模型。

关联首先锚定当前球手的可信 RTMW 手腕，再寻找邻近的握把框。握把缺失时明确记录 `rtmw_wrists` 回退；手腕锚点缺失时不随意选一根球杆。杆身中心必须落在握把到杆头的合理区间，并通过距离与共线性检查，避免选择另一球手或背景亮线。完整三类框、分数和关联失败原因保存至 `swingtrace_detections.json`。

杆头缺失时保持缺失，不用杆身框角点补成一次“检测”。框中心分别适配旧接口的 `shaft`、`hosel` 两列，后者仅是兼容列名，不表示真正测量了杆颈。不会生成 heel/toe 三个额外标记。MixSTE 仍为 17+2；球杆三维结果受代理点与训练标记差异影响，不能当成标定后的真实几何。

## 球的放置位置

默认复用 YOLOE 在准备姿势附近寻找球。也可通过 `--ball-position X Y` 指定原图像素坐标，必须在画面内。手动位置只提供空间锚点，不代表该帧检测到了球，更不代表已经触球。

P7 继续在人体动作约束的下杆窗口内，结合杆头接近球、球在原位/离开原位的图像证据判断。证据不足时保留原算法的回退来源，例如 `wrist_return`。仅有杆头框覆盖球或框中心距离接近零，不能宣称准确捕获触球瞬间。

## 十帧规则

沿用原流程的阶段定义、人体规则、顺序约束和阈值。球杆输入改为 SwingTrace 检测框代理点，进入原球杆清理、跟踪及 MixSTE 流程；不以新模型分数替换动作识别置信度。

| 帧 | 主要依据 | 球杆／球数据用途与回退 |
| --- | --- | --- |
| P1 | 准备姿势结束、起杆开始 | 原球杆静止证据；补充杆头与球放置点距离 |
| P2 | 上杆段杆身接近水平 | 关联后的杆身—杆头方向；不足时记录前导臂进度回退 |
| P3 | 上杆段前导臂经过水平 | RTMW 人体/MixSTE 依据；球杆检测作为辅助记录 |
| P4 | 上杆顶点 | 杆身方向反转与手腕高点互证；记录实际顶点来源 |
| P5 | 下杆段前导臂经过水平 | RTMW 人体/MixSTE 依据；球杆检测作为辅助记录 |
| P6 | 下杆段杆身接近水平 | 关联后的杆身—杆头方向；不足时记录前导臂进度回退 |
| P7 | 下杆窗口内击球附近 | 球离开放置点、杆头与球接近互证；保留触球区间或手腕回退，禁止将位置锚点当成触球确认 |
| P8 | 击球后双臂伸展窗口内杆身接近水平 | 双臂伸展筛选后使用球杆方向；不足时记录前导臂进度回退 |
| P9 | 送杆段手臂经过水平 | 人体依据，按视角使用原二维/三维选择规则 |
| P10 | 收杆时双手举高且靠近头部 | 人体与完整挥杆覆盖检查；不因检测框存在而强行补齐 |

`identified_frames.json` 和 `frame_evidence.json` 每帧包含：实际 `selector_source`、对应规则、三类选中框及置信度、握把关联来源、杆身代理二维倾角、杆头中心/框边界与球的距离、球位置来源，以及 P7 原始诊断。

其中二维倾角是便于复核的原始观测；正式选帧仍经过原有跟踪、三维重建和视角处理，不应把这一字段误当作唯一选择评分。`raw_pair_usable` 也只表示检测关联通过，不保证后续跟踪没有拒绝该观测。`club_observation_kind` 标记为 `box_centre_pair` 或 `partial_missing_or_rejected_boxes`。原 JSON/NPZ 的兼容字段 `club_evidence=complete` 仅表示当前 17+2 的两列通过旧规则，不代表测得真实球杆端点或 ViTPose 的五个标记。

## 自检

```powershell
.\rtmw_workflow\.venv\Scripts\python.exe -m rtmw_workflow self-test --cpu-threads 4
```

运行纯合成单元/回归测试及本地权重的一张 640×640 空白图推理；不调用视频解码或完整处理入口。报告保存在 `outputs/self_test_swingtrace.json`。`check` 与 `video`/`batch` 是另外的入口，本次没有运行。
